# 设计说明

## 数据流

```text
Markdown/TXT → Document → SentenceSplitter → Node → Embedding
                                                   ↓
                                       SimpleVectorStore + Docstore
                                                   ↓
问题 → 可选历史改写 → 向量/BM25 → 可选 RRF → 可选 CrossEncoder
                                                   ↓
                                    带来源的上下文 → LLM → 回答
```

`Config` 是不可变配置；模型工厂显式注入索引，避免触发 LlamaIndex 默认远程模型。demo 的 Embedding 继承 LlamaIndex BaseEmbedding，真实模式使用官方 Ollama 集成。

索引逻辑保留在一个模块内，不为尚不存在的后端创建抽象工厂。文档 ID 是路径，重命名等价于删除加新增。修改文档会删除旧节点并重新生成，未变文档保留原节点。数据目录有效但变空时，ingest 将同步为零文档索引。

增量更新在内存中完成，新版本完整持久化后替换指针；读者加载一次指针，因此不会读取半写入的快照。这是小型本地语料的策略，完整快照复制会随语料增大而变贵。

## 刻意保留的学习边界

- 没有前端、PDF OCR、Chroma、多租户权限、认证或分布式任务；这些不是当前运行前提。
- Markdown 以纯文本处理，尚不提取章节结构。
- LlamaIndex 原生向量存储适合学习；每次查询加载索引不是高吞吐架构。
- BM25 每次查询扫描语料，CrossEncoder 每次创建；缓存和倒排索引为后续优化。
- 每个节点携带来源文件名，无页码；不会生成不存在的 PDF 页码。
- 普通生成有证据提示词但无强制语义校验；Workflow 的模型判断也可能出错。
- Workflow 当前先生成候选回答再做证据检查，便于复用核心路径但会多消耗一次生成。学习后可拆成先检索、后检查、再生成。
- 检索参数默认值是可运行起点，不是性能最优结论。
- Agent trace 记录工具输入输出，不记录私有推理；实际模型工具选择需单独测试。
- Token 计费、完整追踪平台、自动 LLM 判分未实现。
- 模型下载与 Ollama 安装由使用者执行，项目不会自动修改系统环境。

## 验证策略

离线测试覆盖增量更新、删除、无变更、失败快照、配置失配、空语料、来源过滤、检索指标、API 校验、流式协议、计算器与 Workflow。模型替身验证生成接口契约，但不等于真实 Ollama 或真实重排模型的端到端评估。
